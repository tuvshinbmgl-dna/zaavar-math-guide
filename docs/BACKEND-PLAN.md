# Заавар — сервер талын төлөвлөгөө (тэмцээн, төлбөр, админ)

> **Статус: ТӨЛӨВЛӨГӨӨ. Код бичигдээгүй.** Энэ баримт нь `ARCHITECTURE.md` §6-д
> "сервер шаардана" гэж тэмдэглэсэн 3 боломжийг хэрхэн хийхийг судалж, сонголт
> бүрийн үнэ, эрсдэл, ажлын хэмжээг харьцуулна. Шийдвэрийг эзэмшигч гаргана.
>
> Судалгаа хийсэн огноо: 2026-08-02. Үнэ, хязгаар өөрчлөгддөг тул хэрэгжүүлэхийн
> өмнө эх сурвалжийг дахин шалгана уу (эх сурвалжийг доор жагсаав).

---

## 1. Яагаад эдгээрт сервер хэрэгтэй вэ

Одоогийн Заавар нь **бүртгэлгүй, өгөгдлийн сангүй**. Суралцагчийн бүх төлөв
(`XP`, `явц`, `цуврал`, `эрдэнэ`) тухайн хөтчийн `localStorage`-д сууна. Энэ нь
маш хямд (Render-ийн үнэгүй instance хангалттай), нууцлалд ээлтэй (хувийн өгөгдөл
сервер рүү явахгүй), эвдрэх зүйл бага гэсэн давуу талтай.

Гэхдээ дараах 3 зүйлийг **зарчмын хувьд** клиент дээр хийж болохгүй:

| Боломж | Яагаад клиент дээр болохгүй вэ |
|---|---|
| **Тэмцээн (leaderboard)** | Хэрэглэгч А-гийн оноог хэрэглэгч Б харах ёстой. Хуваалцсан хадгалалт = сервер. Мөн `localStorage`-ийг хэрэглэгч гараар засаж болдог тул оноог сервер талд баталгаажуулах ёстой. |
| **Төлбөр** | Төлбөр төлсөн эсэхийг клиент шийдвэл хэн ч `localStorage`-д `paid:true` бичээд тайлж чадна. Мөн QPay-ийн callback серверийн хаяг руу ирнэ. |
| **Админ панел** | Контент засварыг **бүх** хэрэглэгч харах ёстой. Клиент дээрх засвар зөвхөн тухайн хөтөч дээр үлдэнэ. |

Бусад Duolingo механик (XP, түвшин, эрдэнэ, өдрийн даалгавар, авдар, дэлгүүр,
цуврал хамгаалагч, XP хурдасгагч, хувийн дээд амжилт) **сервергүйгээр
хэрэгжсэн** — `J-GAMIFY` + `F-QUESTS`-ыг үзнэ үү.

---

## 2. Санал болгож буй бүтэц

```
Хөтөч ──HTTPS──> Flask (Render) ──> Postgres (Neon, үнэгүй)
                    │
                    ├──> QPay Merchant API v2   (нэхэмжлэх үүсгэх)
                    └──< QPay callback          (төлөгдсөнийг мэдэгдэх)
```

### 2.1 Өгөгдлийн сан

| Сонголт | Үнэ | Гол эрсдэл |
|---|---|---|
| **Neon** (санал болгож буй) | Үнэгүй эгэл хэмжээ **хугацаагүй** | Идэвхгүй үед "унтдаг" — эхний хүсэлт удаан |
| Render Postgres үнэгүй | 256 МБ RAM / 1 ГБ, **30 хоногийн дараа өгөгдлийг УСТГАНА** | Сургалтын өгөгдөлд огт тохиромжгүй |
| Render Postgres Basic-256MB | ~$7/сар | Хамгийн хямд найдвартай хувилбар |
| SQLite файл | 0 | Render-ийн үнэгүй instance-ийн диск **түр зуурын** — deploy бүрд арчигдана |

**Дүгнэлт:** үнэгүй эхлэх бол Neon; орлоготой болмогц Render Basic руу шилжинэ
(нэг `DATABASE_URL` солих ажил).

### 2.2 Бүртгэл (auth)

Одоогийн "локал профайл" (нэр + PIN) нь сервер талд утгагүй. Гурван хувилбар:

1. **Google Sign-In** — үнэгүй, нууц үг хадгалахгүй, сурагчдын ихэнхэд Gmail байдаг.
   *Санал болгож буй.*
2. **И-мэйл + нэг удаагийн холбоос** — SMTP хэрэгтэй (Resend/Postmark үнэгүй эгэл).
3. **Утас + SMS код** — Монголд SMS gateway төлбөртэй, сурагчдад утас байхгүй байж
   магадгүй. Хамгийн үнэтэй, хамгийн бага давуу талтай.

⚠️ **Насанд хүрээгүй хүний өгөгдөл.** Сурагчид ихэвчлэн 18-аас доош. Бүртгэл
нэвтрүүлмэгц Монголын Хүний хувийн мэдээлэл хамгаалах тухай хуулийн дагуу
зөвшөөрөл, хадгалах хугацаа, устгах эрхийг тодорхойлсон нууцлалын бодлого
шаардлагатай. Хуульчтай зөвлөнө үү — энэ бол техникийн биш, эрх зүйн ажил.

### 2.3 Хамгийн бага хүснэгтүүд

```sql
users(id, provider, provider_uid, display_name, created_at, deleted_at)
progress(user_id, subject, payload_json, updated_at)   -- localStorage-ийн толь
xp_events(id, user_id, subject, kind, amount, created_at)  -- тэмцээний эх сурвалж
subscriptions(user_id, plan, status, started_at, expires_at)
payments(id, user_id, provider, provider_invoice_id, amount, status, raw_json, created_at)
admin_audit(id, admin_user_id, action, target, diff_json, created_at)
```

`xp_events`-ийг **үйл явдлын жагсаалтаар** хадгална (нийлбэр талбар биш) — тэгвэл
хууран мэхлэлтийг эргэн шалгах, буруу оноог буцаах боломжтой.

## 3. Тэмцээн (leaderboard)

Duolingo-гийн загвар: ~30 хүний **7 хоногийн лиг**, XP-ээр эрэмбэлнэ, дээд хэсэг
дэвшиж, доод хэсэг буурна, долоо хоног бүр тэглэгдэнэ.

**Заавар-т тохируулах санал:**

- Лигийн хэмжээ 20–30 сурагч, санамсаргүй бүлэглэнэ (сургуулиар биш — жижиг
  сургуульд өрсөлдөөн үүсэхгүй).
- Зөвхөн **өнөөдрийн/долоо хоногийн** XP-ийг харуулна, нийт XP-ийг биш — шинэ
  хэрэглэгч ялах боломжтой байх ёстой.
- **Нэр нууцлах горим** заавал байх: сурагч "Сурагч #4821" гэж оролцох сонголттой.
- Доошоо буух шийтгэлийг зөөлрүүлнэ (Duolingo-гийнх шиг хатуу биш) — манай апп
  "алдвал зүгээр" зарчимтай.

**Хууран мэхлэлтээс сэргийлэх:** XP-ийг клиент илгээх боловч сервер
`xp_events`-д хязгаар тавина (ж: хичээл тутам 1 удаа, өдөрт дээд тал нь N XP,
хичээл дуусгасан хугацаа хэт богино бол тэмдэглэнэ).

**Ажлын хэмжээ:** бүртгэл + `xp_events` + 2 API + 1 хуудас ≈ 3–5 өдөр.

## 4. Төлбөр

### 4.1 ⚠️ Эрх зүйн саад — үүнийг эхэлж шийднэ

Одоогийн бүх контент нь **БШУЯ-ны сурах бичгийн ГАРЧИГ, бүтэц дээр** үндэслэсэн.
Хичээлийн текстийг агент өөрөө зохиосон ч бүтэц, дараалал, сэдвийн нэр нь албан
ёсны сурах бичгээс гаралтай. **Үүнийг мөнгө авч зарах нь зохиогчийн эрхийн
асуудал үүсгэж болзошгүй.** Төлбөр нэвтрүүлэхээс өмнө:

1. БШУЯ-наас **бичгээр** зөвшөөрөл авах (`ARCHITECTURE.md` §7-д дурдсан хуудас
   үзүүлэх зөвшөөрөлтэй хамт нэг өргөдлөөр асууж болно), эсвэл
2. Төлбөрийг **сурах бичгийн контентод биш**, зөвхөн өөрсдийн нэмүү үнэ цэнэ дээр
   тавих: AI багшийн ярианы хязгаар, дэлгэрэнгүй шинжилгээ, эцэг эхийн тайлан,
   офлайн PDF, сурган хүмүүжүүлэгчийн самбар.

**Санал: 2-р зам.** Хөтөлбөр бүхэлдээ ҮНЭГҮЙ хэвээр (нийтийн эрх ашиг), төлбөр
зөвхөн нэмэлт үйлчилгээнд. Энэ нь эрх зүйн эрсдэлгүй, ёс зүйн хувьд ч зөв.

### 4.2 Монголын төлбөрийн сувгууд

| Суваг | Тайлбар |
|---|---|
| **QPay** | Монголын де-факто стандарт. Merchant API v2 — нэхэмжлэх үүсгэх → QR/deeplink → банкны апп → сервер рүү callback. Бараг бүх банк уншина. |
| SocialPay (Голомт) | Тусдаа гэрээ, өөр API |
| Storepay / Pocket | Хэсэгчилсэн төлбөр — сурагчийн эцэг эхэд тохиромжтой байж болно |
| Stripe / Paddle | Монголын мерчант дансыг найдвартай дэмждэггүй — гадаадын картад л |

**QPay-ийн урсгал (v2):**

1. Токен авах (merchant хэрэглэгч/нууц үг → `access_token`).
2. `POST /invoice` — дүн, тайлбар, `callback_url` илгээж нэхэмжлэх үүсгэнэ.
3. Хэрэглэгчид QR эсвэл банкны deeplink үзүүлнэ.
4. Төлөгдөхөд QPay `callback_url` руу дуудна → сервер `payments`-д бичнэ.
5. Callback-ийг **шууд битгий итгэ** — `GET /payment/check`-ээр дахин баталгаажуулна.

Мерчант болохын тулд аж ахуйн нэгжийн гэрчилгээ, дансны мэдээлэл, гэрээ шаардана
(support@qpay.mn).

⚠️ **Би төлбөрийн бүртгэл үүсгэхгүй, API түлхүүр оруулахгүй.** Merchant данс
үүсгэх, түлхүүрийг Render-ийн орчны хувьсагчид тавих ажлыг эзэмшигч өөрөө хийнэ.

### 4.3 Багц (санал)

| Багц | Үнэ/сар | Агуулга |
|---|---|---|
| Үнэгүй | 0₮ | Бүх хичээл, түвшин тогтоох, баталгаа, mock, XP/даалгавар — **бүрэн** |
| Дэмжигч | 9,900₮ | AI багштай хязгааргүй яриа, дэлгэрэнгүй сул тал шинжилгээ, PDF тайлан |
| Гэр бүл | 19,900₮ | 4 хүртэл сурагч, эцэг эхийн нэгдсэн тайлан |

**Ажлын хэмжээ:** QPay интеграц + захиалгын төлөв + хаалт ≈ 5–8 өдөр (мерчант
гэрээний хугацаа тооцоогүй).

## 5. Админ панел

### 5.1 Гол бэрхшээл: Render-ийн файлын систем түр зуурынх

Render-ийн үнэгүй instance дээр `data/*.json`-д бичсэн засвар **дараагийн deploy
эсвэл дахин ачаалалтад арчигдана**. Тиймээс "JSON-г шууд засдаг" админ панел
ажиллахгүй. Гурван зам:

| Зам | Хэрхэн | Дүгнэлт |
|---|---|---|
| **A. GitHub API-аар commit** | Админ засвар хийхэд сервер GitHub API-аар `data/*.json`-г шинэчилж commit хийнэ → Render дахин deploy хийнэ | Түүх үлдэнэ, rollback хялбар, өгөгдлийн сан хэрэггүй. **Санал болгож буй.** |
| B. Postgres-д контент хадгалах | JSON-г файлаас биш DB-ээс уншина | Уян хатан, гэхдээ бүх `store.py`-г дахин бичнэ |
| C. Зөвхөн локал админ | Админ панел зөвхөн хөгжүүлэгчийн машин дээр ажиллана, үр дүнг git-ээр түлхнэ | Хамгийн хямд, өнөөдөр ажиллана |

### 5.2 Хэрэгцээт дэлгэцүүд

1. **Контент засварлагч** — хичээл, асуулт, баталгааны даалгаврыг вэбээс засах;
   хадгалахын өмнө JSON схем шалгах, KaTeX-ийг `throwOnError`-оор шалгах
   (`KATEX-FIX-1`-д гарсан 59 нуугдмал алдааг санаарай).
2. **Контентын эрүүл мэнд** — эвдэрсэн `lesson_id`, хоосон сэдэв, хариултын
   тархалтын хазайлт, хуудасны эшлэл дутуу хичээлийг жагсаана.
3. **Хэрэглээний хураангуй** — хичээл тус бүрийн үзэлт, дундаж дүн, хамгийн олон
   алдагддаг асуулт. (Зөвхөн нэгтгэсэн тоо — хувь хүний өгөгдөл биш.)
4. **Захиалга ба төлбөр** — гүйлгээний жагсаалт, гараар сунгах/цуцлах.
5. **Аудит** — админы үйлдэл бүрийг `admin_audit`-д бичнэ.

### 5.3 Хамгаалалт

- Админыг `users.role='admin'` талбараар, эсвэл `ADMIN_EMAILS` орчны хувьсагчаар
  тодорхойлно. **Хатуу бичсэн нууц үг ХЭРЭГЛЭХГҮЙ.**
- Бүх админ маршрутыг session шалгалтаар хамгаална, CSRF токен ашиглана.
- Уншиж/бичих эрхийг тусад нь (зөвхөн харах админ байж болно).

**Ажлын хэмжээ:** 1 ба 2-р дэлгэц ≈ 4–6 өдөр; бүгд ≈ 10–14 өдөр.

## 6. Үе шаттай хэрэгжүүлэлт

| Үе | Агуулга | Урьдчилсан нөхцөл |
|---|---|---|
| **B0** | Одоогийн байдал — сервергүй гэйм давхарга дуусгах | ✅ хийгдсэн (`GAMIFY-1`, `QUESTS-1`) |
| **B1** | Neon DB + Google Sign-In + явцыг үүлэнд нөөцлөх | Нууцлалын бодлого, эцэг эхийн зөвшөөрөл |
| **B2** | `xp_events` + 7 хоногийн лиг | B1 |
| **B3** | Админ — контент засварлагч (A зам, GitHub API) | GitHub token |
| **B4** | QPay + захиалга | Мерчант гэрээ, эрх зүйн шийдвэр (§4.1) |
| **B5** | Эцэг эхийн тайлан, гэр бүлийн багц | B1, B4 |

**Чухал:** B1 хийх хүртэл апп "бүртгэлгүй" давуу талаа хадгална. B1-ийг эхлүүлэх
шийдвэр нь техникийн бус — **хувийн мэдээлэл, хууль, тайлагналын үүрэг** үүсгэнэ.

---

## 7. Юуг НЭВТРҮҮЛЭХГҮЙ байхыг санал болгож байна

- **Эрдэнийг мөнгөөр зарах.** Хүүхдэд чиглэсэн апп дээр бодит мөнгө ↔ дотоод
  валютын эргэлт үүсгэх нь ёс зүйн эрсдэлтэй. Эрдэнэ зөвхөн суралцаж олдоно.
- **Зүрх дуусахад хичээлийг хаах.** Duolingo хаадаг; манай зарчимтай зөрчилдөнө.
- **Алдсан цувралыг мөнгөөр сэргээх.** Loss aversion дээр мөнгө авах нь сурагчид
  тохиромжгүй.
- **Хувь хүний нэрээр нээлттэй тэмцээн.** Анхдагчаар нэр нууцлах.
